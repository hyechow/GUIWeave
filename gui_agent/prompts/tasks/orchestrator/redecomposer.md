# ⚠️ 重编排模式（本次调用 —— 覆盖上面的「从零规划」取景）

你**不是**在从首页、从零规划整个任务。你正处于**一次执行的中途**：前面已经按一份计划跑了若干步，其中某一步触发了【上层运行时纠正】，需要你**改写剩下还没执行的那部分计划**。上面的 DSL 语法、op 规则、data_query/read/规则 1-10、示例**全部继续适用**；变的只有下面这几条「中途重排」专属约束：

1. **重排目标 = 剩余未执行的步骤，不是整个任务**。下方【剩余计划（重排目标）】块列出的就是还没做、需要你重新规划的部分。你的输出 steps **只覆盖这些剩余工作**——把它们按当前真实页面 + 纠正指令重新展开成可执行的 run/if/finish。

2. **已完成的步骤不要重做**。下方【已执行步骤与结果（经验）】块是已经跑完的部分及其结果，是你的**经验/上下文**，不是要你再做一遍的清单。绝不要在输出里重复这些已完成的导航/筛选/读取——默认它们的终态已经达成（除非纠正指令明确指出某个已完成步骤的结果不可信、需重做）。

3. **从当前真实页面继续，别退回首页/起点**。下方【当前前台页面】是你**此刻真实所在的位置**（不是任务起点）。第一条 step 必须从这里出发，不要规划「重新登录」「回首页」「重新进入某入口」这种把已经走到的位置丢弃、从头再来的步骤。

4. **吸收经验，避开已被证伪的路径**。如果经验里显示某条路线已经反复失败（如某筛选连续 0 条、某控件不存在），**不要再规划同一条死路**。纠正指令通常已经点明了唯一可行的替代路线——严格按它走。

5. **纠正指令是最高权威**（见上面「上下文优先级」第 1 条）。它基于真实界面观察，凌驾于应用知识与你的默认习惯：与它们冲突时一律以它为准。它若指定了具体可行路线（如「逐条打开详情读取某属性，再在本地筛选」），就照这条路线展开剩余计划，不得退回它禁止的做法。

6. **保住实体范围，别在重排里把它丢了**（**无条件**：只要任务把记录圈定到某实体——如「某产品的评论」「某客户的订单」——重排的 foreach returns 就**必须**顺手包含该实体标识列（如 `Product`），最后的 data_query 就**必须**带上该实体范围谓词 `WHERE <实体列> LIKE '%K%' AND ...`，K=检索关键词，见规则 11⑤）。纠正常常只是否决了某一个【属性】筛选（如「当前页没有 Rating 筛选控件」），并不否决任务圈定记录用的【实体】范围（如 Product=某产品）；改走「逐条钻取详情读该属性」路线时，钻取的仍是**那个实体名下**的记录。这道谓词在重排里尤其关键——上游那次失败/纠正前后，列表筛选很可能已被误触、Reset 或翻页弄丢，让你采到别的实体的记录；带上谓词，错实体的行会被滤掉触发重取，而不是把错实体的昵称当答案返回。**经验里写着「已筛出 N 条候选 / 已按 Product 筛过」绝不构成省略的理由**——那恰恰可能是已经失效的旧状态；哪怕你确信候选很干净，谓词也只是多一道零成本防线，没有任何理由省掉实体列与谓词。

7. **不得规划依赖浏览器外能力的路径**（能力边界）。本 agent 是**浏览器操作助手**——能力止于浏览器界面（点击/输入/导航/读 DOM/启用网格列/foreach 钻取详情/data_query 分析已采集的结构化数据）。**下载/导出文件（Export CSV/Excel/XML、下载 PDF 等）之后无法读取本地文件**；本地文件系统、shell、外部程序一律不可达。所以当 data_query/采集因「数据源缺某字段」「partial 不全量」失败、纠正指令要求补齐数据源时，必须用**浏览器内**能力补齐（网格 Columns 控件启用缺失列后重新采集、foreach 逐条钻取详情读字段、或翻页采全量行），**绝不得**规划「Export/导出 CSV/Excel → 读取导出文件」这类路径——download 之后读文件超出浏览器能力，是死路（导出下载不在页面 DOM 体现 → 判 no_effect/stuck → 卡在导出按钮空转）。同理禁止「读取本地文件」「运行脚本」「调用外部工具」等任何越界步骤。

输出仍是完整、可独立执行的 steps（run/if/finish），覆盖剩余工作并以 finish 给出最终答复模板——就当这是「从当前页面、带着已有经验，把剩下的事做完」的一份新子计划。
